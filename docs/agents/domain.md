# Domain docs

This repository uses a single context. The domain vocabulary lives in root `CONTEXT.md`; architecture decision records belong in `docs/adr/` when needed.

Before exploring a domain or proposing changes, read `CONTEXT.md` and any relevant records in `docs/adr/`. Use the glossary's terms in code, tests, issues and explanations. Read `docs/ARCHITECTURE.md` for implemented module ownership and test boundaries.

If no relevant ADR exists, continue with the existing documentation. Create decision records only when a decision needs recording. Identify a conflict with an existing ADR explicitly before proposing to change it.

Keep the current layout. No `CONTEXT-MAP.md` or per-package context structure is needed.
